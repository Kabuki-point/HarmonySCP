# 在模拟器验证 SSH 连接功能

- 日期：2026-11-03（Asia/Shanghai）
- 执行者：Codex
- 关联：用户要求用模拟器完成 SSH 测试；分支 `mullen/minest-ssh`，未提交或推送。

## 需求与目的

在前次 x86_64 安装、启动验证的基础上，通过实际页面验证 SSH 协议握手、主机身份确认、密码认证和连接管理，不把编译或宿主机测试视为设备登录成功。

## 具体操作

- 在忽略的 `build/` 中创建临时 Python 环境、Paramiko 环回 SSH 服务和 UI 自动化驱动；不修改系统 SSH、安全或账户配置，测试使用随机合成密码和内存主机密钥。
- 使用 HDC 反向端口转发连接 WSL 测试服务，通过模拟器页面操作表单、核对指纹、确认认证和断开。
- 新增 `docs/validation/emulator-ssh-validation.md` 记录环境、场景、命令、实际结果及限制；更新文档索引和项目进度。
- 保留既有未提交修改；本次不修改应用源码、Native 接口或依赖。

## 验证

实际测试进展与完整结果见 [模拟器 SSH 验证记录](../validation/emulator-ssh-validation.md)。全部结论基于真实模拟器 UI 和匿名服务端事件，不记录密码、私钥或真实账户信息。

- 正确密码登录与主动断开、拒绝指纹且不发送认证、错误密码、服务端关闭、握手取消、不可用端口、切后台断开与回前台，共 7 个场景完成。最终驱动退出 0，输出 `All 7 emulator UI SSH scenarios passed`。
- 在 UI 驱动中独立计算服务端主机密钥 SHA256，与应用显示值逐字比较后才确认认证；服务端事件证明指纹确认前未认证，正确/错误密码分别得到对应结果。
- 服务端关闭第一次超过 8 秒观察窗口；复测从开始操作指纹确认到观察到错误约 17.29 秒（含 UI 操作），保留为检测延迟限制，不宣称即时检测。
- 临时驱动修正了 `No Error` 成功消息判断和输入追加行为；未改应用源码。
- 清理完成：删除本次端口转发（列表返回空）、停止临时服务、删除本地凭据与本地/设备布局文件，重启应用清空表单。未修改系统 sshd 或账户。
- 最终检查：7 项匿名结果均为 passed 且场景名不重复；文档本地链接、空白检查及 README 零字节检查通过。`pgrep` 未找到临时服务，`ss -lnt 'sport = :23222'` 无监听项，HDC 转发列表为空。主动连接清理后的端口出现超时，清理结论以进程和监听表检查为依据。

## 限制与风险

临时 Paramiko 服务与系统 OpenSSH 的配置不同；成功不能外推为任意 WSL / Windows 系统账户均可登录。服务端断开提示存在延迟；ARM64、IPv6、超时与完整设备验收仍需补充。未执行 Hypium，未重新构建 HAP，本次为既有产物测试和文档更新。
