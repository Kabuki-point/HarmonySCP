# 增加 x86_64 模拟器构建

- 日期：2026-11-03（Asia/Shanghai）
- 执行者：Codex
- 关联：用户提供安装错误 `9568347`；按用户要求在合并前的 `mullen/minest-ssh`（起点 `f2ea2f8`）修改，未提交或推送。

## 需求与目的

模拟器安装 HAP 提示 `install parse native so failed`。项目原先仅包含 ARM64 原生库；本次读取目标模拟器 ABI 为 `x86_64`。增加 x86_64 构建与依赖，同时保留 ARM64。

## 具体操作

- `entry/build-profile.json5`：同时启用 `arm64-v8a` / `x86_64`。
- `entry/src/main/cpp/CMakeLists.txt`：校验支持的 ABI 与依赖文件，按 `OHOS_ARCH` 链接对应目录中的静态库。
- `entry/libs/x86_64/`：从官方未修改源码构建 libssh2 1.11.1、OpenSSL 3.5.4 静态库；共用头文件与官方 libssh2 头文件逐字节一致。保留既有 ARM64 静态库。
- `scripts/build-x86_64-deps.sh`：提供固定版本与源码 SHA256 校验的 Linux/macOS SDK 重建流程；仅写入忽略的构建目录及 x86_64 依赖目录。
- `third_party/NOTICE.md` 及 `third_party/licenses/OpenSSL-3.5-LICENSE.txt`：记录来源、工具链、参数、ABI、源码与产物哈希、许可证和未核实事项。
- `docs/validation/native-dependencies.md`：记录重建、打包和设备检查方法；更新项目说明与文档索引。
- 保留既有未提交修改，包括文件权限差异和两个 OHPM 锁文件的换行差异；不修改 AGENTS.md、签名或系统配置。

## 验证

- OpenSSL 官方源码包 SHA256 与官方 `.sha256` 文件一致；libssh2 下载包哈希实测并固定，未验证 PGP 发布者签名。
- 本次实际在 WSL 通过忽略目录中的路径适配器调用 Windows SDK Native `26.0.0.105` / Clang `15.0.4`；`perl Configure linux-x86_64 no-shared no-module no-tests no-asm no-makedepend` 加 OHOS target、sysroot、PIC，`make -j12 build_libs` 退出 0。
- libssh2 通过 CMake 交叉编译和实际链接进行特性检测；`cmake --build build/native-deps/libssh2-verified -j 8` 退出 0，27 个构建步骤完成。
- `readelf -h` 检查四个归档全部 ELF 成员：ARM64 libcrypto / libssh2 为 648 / 26 个 AArch64 成员；x86_64 为 1013 / 26 个 x86-64 成员。ARM64 两库 SHA256 与原记录一致。
- DevEco 自带 Node 调用 `hvigorw.js --mode module -p module=entry@default -p product=default assembleHap --no-daemon`：退出 0，`BUILD SUCCESSFUL`（18.105 秒）。未配置签名，生成 unsigned HAP。
- Python ZIP / ELF 检查：HAP 包含两种 ABI 的 libentry.so 与 libc++_shared.so，ELF machine 分别为 183 / 62。`readelf -d` 确认 x86_64 libentry.so 仅依赖 SDK 系统库和 C++ 运行库，无宿主机 libcrypto.so 依赖。
- `hdc install <HAP>`：`install bundle successfully`；`hdc shell aa start -a EntryAbility -b com.example.har_scp`：`start ability successfully`；后续两次 `pidof` 均返回同一应用进程。`hilog -x -T HarmonySCP` 未返回该标签日志，不据此宣称 SSH 功能通过。
- `bash -n scripts/build-x86_64-deps.sh` 通过；本次修改文件的 `git diff --check` 通过。全仓检查发现两个既有 OHPM 锁文件存在 CRLF 空白提示，保留原状。
- 独立只读审查未发现 P0/P1/P2 实质问题；文档本地链接与空白检查通过，根目录 README 保持零字节。

## 限制与风险

- 未实测 SSH 握手、指纹确认、密码登录、取消和断开，也未验证 ARM64 真机运行；安装和启动不代表完整设备验收。
- 提供的 Linux/macOS SDK 重建脚本完成语法检查；当前只有 Windows SDK，未实测该脚本完整流程。实际产物使用同一源码与目标参数，通过本地 WSL 适配流程生成；不同工具链或构建路径的逐字节可复现性未验证。
- ARM64 继续使用既有来源不完整的预编译依赖；x86_64 使用 OpenSSL 3.5.4，两种 ABI 的加密后端版本不同，不能混用静态库。未完成安全补丁或供应链审计。
